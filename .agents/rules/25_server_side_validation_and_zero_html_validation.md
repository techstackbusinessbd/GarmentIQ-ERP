# রুল ২৫: অল-টাইম সার্ভার-সাইড ভ্যালিডেশন ও জিরো এইচটিএমএল ভ্যালিডেশন নীতি (Server-Side Validation Authority & Zero HTML Validation Rule)

> **পলিসি আইডি**: `RULE-25-SERVER-SIDE-VALIDATION`  
> **ক্যাটাগরি**: ফ্রন্টএন্ড UI/UX ও ব্যাকএন্ড এপিআই ভ্যালিডেশন গভর্নেন্স  
> **প্রযোজ্য ক্ষেত্র**: সমগ্র গার্মেন্টস ইআরপি প্ল্যাটফর্মের সকল ফ্রন্টএন্ড ফর্ম, ইনপুট ফিল্ড ও ব্যাকএন্ড REST কন্ট্রোলার  
> **অনুমোদনকারী**: 👨‍💼 তানভীর আহমেদ *(Chief Architect)* & 👩‍💻 সাদিয়া জাহান *(Frontend Lead)* & 👩‍🔬 ফারহানা চৌধুরী *(QA Lead)*  
> **সর্বোচ্চ নীতি**: **"ব্রাউজারের কোনো নেটিভ এইচটিএমএল বাবল নয়; ১০০% ভ্যালিডেশনের একক অথরিটি ব্যাকএন্ড সার্ভার।"**

## ১. কোর ভিশন ও প্রয়োজনীয়তা (Why This Rule?)

সাধারণ ওয়েব অ্যাপ্লিকেশনে ব্রাউজারের নেটিভ ভ্যালিডেশন (`required`, `pattern`, ইত্যাদি) ব্যবহার করলে ব্রাউজার নিজস্ব কুৎসিত "Please fill out this field" পপআপ বা বাবল প্রদর্শন করে, যা একেক ব্রাউজারে (Chrome, Firefox, Safari, Edge) একেক রকম দেখায় এবং এন্টারপ্রাইজ ড্যাশবোর্ডের প্রিমিয়াম ভিজ্যুয়াল অভিজ্ঞতাকে মারাত্মকভাবে ক্ষুণ্ণ করে। 

তাছাড়া ক্লায়েন্ট-সাইডে ডুপ্লিকেট ভ্যালিডেশন লজিক লিখলে ব্যাকএন্ডের ডোমেন রুলস ও ডেটাবেজ কনস্ট্রেইন্টের সাথে অমিল তৈরি হয়। তাই গার্মেন্টস ইআরপিতে:
1. **এইচটিএমএল নেটিভ ভ্যালিডেশন সম্পূর্ণ নিষিদ্ধ**।
2. **সার্ভার-সাইড ভ্যালিডেশনই হবে পরম সত্যের উৎস (Single Source of Truth)**।
3. ফর্ম সরাসরি সার্ভারে সাবমিট হবে এবং ব্যাকএন্ডের ফেরত দেওয়া নির্ভুল ফিল্ড এরর মেসেজ সরাসরি ফ্রন্টএন্ড ফিল্ডের নিচে মানবিক ইংরেজিতে ডায়নামিকভাবে রেন্ডার হবে।

## ২. মৌলিক নীতিসমূহ (Core Tenets)

### ১. ১০০% ফর্মে `noValidate` বাধ্যতামূলক
ফ্রন্টএন্ডের প্রতিটি `<form>` ট্যাগে বাধ্যতামূলকভাবে `noValidate` প্রোপার্টি থাকতে হবে:
```tsx
// ❌ সম্পূর্ণ নিষিদ্ধ (ব্রাউজার বাবল দেখাবে)
<form onSubmit={handleSubmit}>
  <input type="email" required />
</form>

// ✅ বাধ্যতামূলক এন্টারপ্রাইজ স্ট্যান্ডার্ড
<form noValidate onSubmit={handleSubmit}>
  <input type="email" />
</form>
```

### ২. নেটিভ এইচটিএমএল ভ্যালিডেশন প্রপস বর্জন
- ইনপুট ফিল্ডে ব্রাউজারের ডিফল্ট ইন্টারসেপশন ট্রিগার করে এমন অ্যাট্রিবিউট (যেমন: ব্রাউজার-লেভেল `pattern="..."`, `required`, ব্রাউজার টাইপ ব্লকিং) ফ্রন্টএন্ডে ব্যবহার করে সাবমিট আটকানো যাবে না।
- ইউজার সাবমিট বাটনে ক্লিক করলে ডেটা সরাসরি ব্যাকএন্ড এপিআই-এ যাবে।

### ৩. ব্যাকএন্ড সার্ভার-সাইড ভ্যালিডেশনের সার্বভৌমত্ব (Server-Side Authority)
- সকল ভ্যালিডেশন (যেমন: ফিল্ড不能为空, অক্ষরের দৈর্ঘ্য, রেঞ্জ, ইউনিকনেস, ডোমেন লজিক, সাইজ-কালার রেশিও) ব্যাকএন্ডের স্প্রিং বুট DTO (`@Valid`, `@NotBlank`, `@Size`, `@Min`, `@Pattern`, `@Email`) এবং সার্ভিস লেয়ারে কঠোরভাবে যাচাই হবে।
- ইনভ্যালিড ডেটার ক্ষেত্রে ব্যাকএন্ড `GlobalExceptionHandler` থেকে প্রমিত `ApiResponse.error(...)` এবং `fieldErrors` ম্যাপ ফেরত দেবে:
```json
{
  "success": false,
  "message": "Validation failed. Please verify the submitted data.",
  "data": {
    "username": "Username must be between 3 and 50 characters",
    "email": "Please provide a valid corporate email address"
  },
  "timestamp": "2026-10-19T13:25:00Z"
}
```

### ৪. ফ্রন্টএন্ড এরর হ্যান্ডলিং ও ইনলাইন রেন্ডারিং (Graceful Error Mapping)
- ফ্রন্টএন্ড সার্ভার থেকে আসা `data` (ফিল্ড এরর ম্যাপ) গ্রহণ করে স্ব স্ব ফিল্ডের নিচে সুন্দর ইনলাইন হেল্পার মেসেজ (রঙ: `#f43f5e` / `rose-500` বা অ্যাম্বার) আকারে প্রদর্শন করবে।
- কোনো ফিল্ডে ইউজার টাইপ করা শুরু করলে বা ভ্যালু পরিবর্তন করলে সেই ফিল্ডের পূর্ববর্তী সার্ভার এরর স্বয়ংক্রিয়ভাবে ক্লিয়ার হয়ে যাবে।
- একাধিক ফিল্ডে এরর থাকলে বা গ্লোবাল বিজনেস ভ্যালিডেশন ফেইল করলে সেন্ট্রাল টোস্টে (`sonner`) স্পষ্ট মানবিক ইংরেজি মেসেজ ভেসে উঠবে।

## ৩. ফ্রন্টএন্ড সেন্ট্রাল এরর পার্সিং ইউটিলিটি প্যাটার্ন

ফ্রন্টএন্ডে সকল এপিআই কলের জন্য একটি সেন্ট্রাল এরর এক্সট্র্যাক্টর ব্যবহার করতে হবে:

```typescript
/**
 * [EN] Extracts server-side field validation errors from API response envelope.
 * [BN] এপিআই রেসপন্স এনভেলপ থেকে সার্ভার-সাইড ফিল্ড ভ্যালিডেশন এরর সংগ্রহ করা।
 */
export function extractFieldErrors(error: unknown): Record<string, string> {
  if (
    axios.isAxiosError(error) &&
    error.response?.data?.data &&
    typeof error.response.data.data === 'object' &&
    !Array.isArray(error.response.data.data)
  ) {
    return error.response.data.data as Record<string, string>;
  }
  return {};
}
```

## ৪. টিমের দায়িত্ব বণ্টন (Role Ownership)

| সদস্য | দায়িত্ব ও করণীয় |
| :--- | :--- |
| **👨‍💼 তানভীর আহমেদ**<br>*(Architect & PM)* | বায়ার অর্ডার, কাটিং ও সকল ডোমেনের ব্যবসায়িক রুলস ও ফিল্ড কনস্ট্রেইন্ট স্পেসিফিকেশনে স্পষ্টভাবে নির্ধারণ করা। |
| **👨‍💻 আরিফুল ইসলাম**<br>*(Tech Lead & Backend)* | স্প্রিং বুটের DTO-তে Jakarta Validation (`@Valid`, `@NotNull`) এবং কাস্টম বিজনেস ভ্যালিডেটর দিয়ে ১০০% সার্ভার ভ্যালিডেশন ও প্রমিত `fieldErrors` রেসপন্স নিশ্চিত করা। |
| **👩‍💻 সাদিয়া জাহান**<br>*(Frontend Engineer)* | সকল ফর্মে `<form noValidate>` নিশ্চিত করা, ব্রাউজার নেটিভ ভ্যালিডেশন বন্ধ রাখা এবং সার্ভার এরর রেসপন্স স্ব স্ব ফিল্ডের নিচে নিখুঁত স্টাইলে রেন্ডার করা। |
| **👩‍🔬 ফারহানা চৌধুরী**<br>*(Lead QA & Gatekeeper)* | কোনো ফর্মে ব্রাউজারের ডিফল্ট বাবল দেখা যায় কিনা বা সার্ভারের কোনো এরর মেসেজ ইউআই-তে মিসিং হয় কিনা তা টেস্ট করে রিলিজ গেট আটকে দেওয়া। |

## ৫. কিউএ চেকলিস্ট (QA Acceptance Criteria)

- [ ] ফর্মে কোনো নেটিভ ব্রাউজার পপআপ বা বাবল ("Please fill out this field") কখনো প্রদর্শিত হয় না।
- [ ] প্রতিটি ফর্মে `<form noValidate>` অ্যাট্রিবিউট যুক্ত আছে।
- [ ] খালি বা ভুল ডেটা নিয়ে সাবমিট বাটনে চাপ দিলে সরাসরি সার্ভার এপিআই কল হয়।
- [ ] সার্ভারের HTTP 400 এরর রেসপন্স পার্স করে সংশ্লিষ্ট ইনপুটের ঠিক নিচে সার্ভারের পাঠানো স্পষ্ট মানবিক ইংরেজি টেক্সট ফুটে ওঠে।
- [ ] ফিল্ডে পুনরায় ইনপুট দেওয়া শুরু করলে এরর স্টাইল ও মেসেজ রিসেট হয়ে যায়।
- [ ] গ্লোবাল এররগুলো প্রফেশনাল `sonner` টোস্টে প্রদর্শিত হয়।
